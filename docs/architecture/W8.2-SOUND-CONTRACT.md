# W8.2 — Sound + Impact Tuning Contract

Date: 2026-10-08

Status: **IMPLEMENTATION / PENDING CI**

## Scope

Add an original, asset-free semantic sound layer to the accepted
Mass Runner W8.1 polished experience.

Keep all existing MassRunnerModel mechanics, five authored levels,
score, speed, collisions, steering and finish semantics unchanged.

## Audio boundary

`PlatformBridge.isAudioEnabled` and `onAudioEnabledChange`
are authoritative, including YouTube's runtime mute toggle.

Only two narrow integration edits beyond Mass Runner are permitted:

- `src/factory/GameModule.ts` — optional `setAudioEnabled` contract;
- `src/main.ts` — forward initial and changed platform mute state.

No platform/SDK implementations, shared renderer, prior proof games,
Core, testing runtime or distribution adapters may change.

## Sound palette

- pickup — bright, short 2-layer tone, pitch increases with mass;
- positive gate — low weight + bright positive accent;
- multiplier gate — extra bass and high transient;
- negative gate — short muted fall;
- hazard — low transient with rough upper edge;
- clear — ascending 3-note sting;
- fail — descending 3-note sting;
- MASSIVE — bass + rising completion sequence.

All audio is procedural using browser oscillators: zero licensed
samples, zero runtime requests, zero additional dependencies.

## Runtime guarantees

- No AudioContext creation before user gesture.
- Mute disables output immediately, even if a tail is active.
- If audio is disabled, no cue is queued for later playback.
- Cue IDs are consumed monotonically and cannot double-play on redraw.
- `reset` permits new cue IDs on retry.
- Audio failures or unavailable devices cannot block gameplay.
- `?audio=off` disables all sound for deterministic visual evidence.
- `?presentation=baseline` remains soundless.
- The same game works on web, YouTube and playable-ad wrappers.
