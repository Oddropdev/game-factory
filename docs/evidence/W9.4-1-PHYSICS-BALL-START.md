# W9.4-1 — Physics Ball Runner Hero Slice

State: IMPLEMENTATION / CI AND PHYSICAL ANDROID GATE PENDING.

## Why this exists

The original W9.3 soft character and arithmetic-gate Mass Runner remain frozen,
publicly deployed at the accepted 2D/default route and experimentally at /3d/.
W9.4 deliberately pivots to a **different physical rolling-ball game**.
Do not confuse this with a skin swap, and do not reopen MassRunnerModel math.

## Actual prototype

- New opt-in `/ball/` scene, isolated Vite build under `playtest-dist/ball`.
- PlayCanvas 2.22.6 renderer, **Ammo.js/Bullet physics** from self-hosted WASM.
- One real dynamic sphere with gravity, damping, rolling torque and velocity
  clamping. Static segmented track and 4 physically colliding soft bumpers.
- Touch/pointer steering acts on rigidbody force; camera follows physics.
- 6 collectible gems, off-track falling/reset, replay and progress HUD.
- Responsive portrait/landscape CSS, and a read-only browser audit probe.
- Explicit test gate: 3 viewport renders, momentum, lateral steering,
  real collision callback, replay and 3 repeated real-input steering tests.

## High-ROI scope lock

No commercial telemetry, no game factory abstraction, no level catalogue,
no procedural art engine and **no changes** to the accepted 2D/3D Mass Runner
levels/model, packages, CI or manual Pages deployment.

The game is deliberately separated because true ball motion cannot retain
MassRunnerModel's original lane/forward-tick logic without concealing physics.

## ITHappy asset handling

The owner's ITHappy Casual Knockout archive contains 172 FBX props, e.g.
SM_Trap_Roller, SM_Trap_Candy, SM_Platform_Round, and SM_Pillar_Rounded.
The purchased raw archives are **not** in this public repository. This first
physics gate uses simple original geometric stand-ins, with matching inexpensive
collision proxies. Later import only 3–5 GLB models after authorized local
conversion, a visual/device comparison and a distribution rights check.

The imported GLBs would be browser-accessible; do not assume private licensing
means permission to publish raw source bundles.

## Acceptance semantics

- `W9_4_1_REAL_PHYSICS_BROWSER_PASS`: CI green on real Ammo browser state.
- `W9_4_1_VISUAL_REVIEW_PENDING`: independent screenshots reviewed but no GO.
- `W9_4_1_ANDROID_GO`: only after physical Android Chrome playtest, controlling
  through touch, actual FPS/thermal observation and owner visual assessment.
- Do not auto-deploy `/ball/` to public Pages; currently the manual W9 publish
  workflow does **not** build the ball, by design.
