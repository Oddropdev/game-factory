# W9.5 Mobile Web Preview — isolated Android/browser staging

## Scope and protection
- Source: `Oddropdev/game-factory`, branch `w9-5-mobile-web-preview` branched from the finished three-world W9.5 branch.
- Does not merge or update `main`, PR #36, PR #37, or the prior game preview.
- Publishes **only** the allowlisted, unlicensed W9.5 build. Do not upload the owner's private ITHappy GLB/ZIP models.
- No production trading/app integrations, telemetry, account system, or exposed credentials.

## Expected mobile URL (only after a successful Pages deployment)
`https://oddropdev.github.io/game-factory/ball/?mode=trilogy`

The Pages homepage redirects to the playable trilogy; the actual game is served under `ball/` with relative Vite asset URLs so it also works from the GitHub Pages project subpath. A fixed repeatable coaster layout can be opened with `&seed=17`.

## Build/deploy
The workflow `.github/workflows/w9-5-mobile-web-preview.yml` runs on pushes to **this preview branch only**. It installs Node.js 24, builds `W95_PUBLIC=1`, runs the existing `check:w9-5:public` allowlist/security check, makes a tiny static redirect homepage, uploads a test ZIP, and attempts to deploy a Pages artifact from `public-site/`. No change to the game's physics, manifests or levels is required.

**Important initial account setting:** If GitHub Pages has never been enabled on this repository, the deployment job may fail until the repository owner goes to **Settings → Pages → Build and deployment → Source: GitHub Actions**. The GitHub Actions token cannot enable Pages itself. Do not interpret a green build job as evidence that the URL is publicly available. Verify the deployment job succeeds and the HTTPS URL actually loads before sharing it as live.

## Android acceptance test
1. Open the verified Pages URL directly in Android Chrome; no computer or local server is needed.
2. Start the game, test horizontal swipe and upward flick, and traverse Crystal Sky → coaster A → Cloud Candy → coaster B → Rainbow Rush.
3. Assess portrait UI, frame smoothness, Android loading time, rail/guard controls, coaster camera, finish and restart.
4. Report device model, visual quality (1–5), input responsiveness (1–5), any errors or performance stutters. A short recording is useful for reproducible defects.

## Failure handling
- If Pages is disabled, enable GitHub Actions as the publishing source; then rerun the **W9.5 Mobile Web Preview** workflow from GitHub Actions or push an isolated branch commit. This preserves the owner-approved W9.5 code.
- If a published route gives 404, check deployment status, the project-site prefix `/game-factory/`, and the `ball/` output layout.
- If model files are absent, that is intentional: licensed art stays owner-local.
- Pages makes the preview **public** to anyone with the link; it is not an access-controlled staging site. Do not use it for unreleased proprietary content.
