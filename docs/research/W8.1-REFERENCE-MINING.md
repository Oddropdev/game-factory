# W8.1 — Reference Mining

Date: 2026-10-08

Status: **REFERENCE PASS / HERO-SLICE INPUT**

## Rule

Commercial games are used as behavioral and presentation references only.

W8.1 does **not** copy:

- source code;
- sprites;
- models;
- textures;
- audio;
- fonts;
- shaders;
- UI artwork;
- proprietary level data.

All hero-slice production visuals are built from original LittleJS primitives.

## Public references

### Tall Man Run

Public store description:

https://play.google.com/store/apps/details?id=com.VectorUpGames.TallManRun

Core reference signal:

- the player's body dimensions visibly encode progression;
- getting taller/wider is the product fantasy, not hidden stat math;
- the end-state promise is readable directly from silhouette.

Mass Runner translation:

**mass must be embodied by the player shape.**

### Going Balls

Public store description:

https://play.google.com/store/apps/details?id=com.pronetis.ironball2

Core reference signal:

- speed, balance and steering are the central sensory problem;
- the player reads danger through track context and motion;
- a simple object can carry the whole game if movement has weight and speed context.

Mass Runner translation:

**track motion, steering lean, shadow and trail should make constant forward velocity feel physical.**

### Stacky Dash

Public store description:

https://apps.apple.com/us/app/stacky-dash/id1515957122

Core reference signal:

- collected value becomes a visible physical stack;
- accumulating more changes the avatar's visual state immediately;
- progression is continuously legible without opening UI.

Mass Runner translation:

**every mass gain should have immediate silhouette/HUD feedback.**

### Bridge Race

Public store description:

https://play.google.com/store/apps/details?id=com.Garawell.BridgeRace

Core reference signal:

- collection is made visible and then converted into forward progress;
- color coding makes ownership/good targets immediately readable;
- collection and expenditure create a strong repeated visual rhythm.

Mass Runner translation:

**good/bad arithmetic choices should be color-readable before text is parsed.**

## General game-feel references

Layered game-feel patterns:

https://github.com/m2-md/game-feel-hitstop-juice

Useful principles:

- small effects should reinforce the same event in one frame window;
- squash/stretch makes mass/compression readable;
- short flashes localize impact in time;
- deterministic shake is testable;
- one impact can drive multiple coordinated presentation channels.

Web game-feel walkthrough:

https://masterallarts.com/learn/web-games-from-zero/05-juice-and-game-feel/

Useful principles:

- particles localize an event in space;
- overshoot/easing turns scale change into a perceptual pop;
- camera movement should support, not obscure, input;
- too much hit-stop can damage control feel.

## Selected hero-slice stack

W8.1 intentionally implements a concentrated visual/feel stack rather than every candidate.

Primary implementation set:

1. embodied mass silhouette;
2. steering lean;
3. squash/stretch + wobble;
4. dynamic shadow;
5. afterimage trail;
6. lane motion streaks;
7. pickup halo + particle burst + numeric delta;
8. world-space gate labels + color hierarchy;
9. positive/negative impact tint;
10. deterministic hazard/multiplier shake;
11. HUD mass pulse;
12. clear/final celebration burst.

These are all game-local.

## Why hit-stop and zoom are reserve

Both can be effective, but they alter temporal/spatial perception strongly enough that they should only be added after the first A/B capture proves the lighter stack is insufficient.

W8.1 avoids changing gameplay simulation time.

## Sound plan — locked, not implemented in W8.1

Sound is high ROI, but must respect the W6 platform audio-enabled contract.

W8.1 therefore locks the semantic sound palette without adding ad-hoc WebAudio inside gameplay:

- pickup: short bright tone, pitch tracks current mass;
- positive gate: transient + low body;
- multiplier: stronger low transient + bright upper layer;
- negative gate/hazard: short dull thud/noise;
- level clear: compact rising sting;
- fail: compact falling sting;
- final MASSIVE: layered low hit + bright completion sting.

Implementation belongs in W8.2 after the visual A/B pass, using a path that can be muted by Web/YouTube/playable-ad platform state.

No commercial-game audio will be reused.

## Hero-slice decision

W8.1 captures Level 1 because it contains, within one short deterministic route:

- pickup;
- hazard avoidance;
- positive gate;
- multiple steering changes;
- finish/clear.

This creates a short baseline/polished A/B that isolates presentation rather than content difficulty.
