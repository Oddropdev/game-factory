# W9.5 — Android phone test over private Wi-Fi

## Quick start (Windows PC and Android on same Wi-Fi)

1. Open the CI artifact `w9-5-android-wifi-playtest-preview` in the W9.5 Mobile LAN Preview GitHub Actions run.
2. Download the artifact ZIP to the Windows PC, and **extract all files** into a normal folder. Do not launch the game from inside the ZIP.
3. Ensure **Node.js 24+** is installed on the PC.
4. Double-click **`Start_Android_Playtest.cmd`**.
5. The black window prints a link in the form `http://192.168.x.x:4177/ball/?mode=trilogy`. Open that exact URL on Android in **Chrome**.
6. If Windows prompts for Node.js network access, permit **Private networks only**. Do **not** enable Public networks and do not configure router port forwarding.
7. Keep the black window open during the test; press **Ctrl+C** to stop.

The script exposes **only** the preview web build on the local network, never raw licensed ITHappy models. It does not publish to GitHub Pages or the internet. Other devices on the **same local network** can access the preview while it is running.

### If the phone cannot connect

- Disable mobile data temporarily, verify phone/PC are on the same Wi-Fi, and avoid guest Wi-Fi / AP isolation.
- Check that the Windows **network profile is Private**, and if prompted, allow Node.js on Private networks. A VPN may interfere.
- Try the printed PC link in the PC's browser to verify the server started.
- Do not use `localhost` or `127.0.0.1` on Android: those address the phone, **not** the PC.
- The ZIP's HTML should not be opened via `file://` on Android: browser module, manifest, WebAssembly and fetch restrictions can block the game.

### Physical mobile test (3–5 minutes)

Use actual Android Chrome. Check: first-frame load, start tap, swipe steering, flick-to-accelerate, first coaster and its mobile camera/orbit, both level transitions, 3 worlds visually loaded, restart, portrait UI clipping, device frame smoothness, heat after 3 minutes. Rotate to landscape only after portrait pass.

Send the minimal feedback: phone model, Chrome version if known, **overall visual quality 1–5**, responsiveness 1–5, any FPS judder, overheat, clipping, crash, and a 10–20-second recording if something breaks.

### Boundary and workflow

This is an **owner-only staging branch** based on Astra's saved W9.5 commit `b26e381`, **not** a merge of Astra's draft PR. It only adds optional LAN serving and instructions. Its GitHub Actions preview deliberately contains no paid ITHappy source files. Android GPU/FPS performance cannot be verified in CI; this is why the real device test is useful.
