# W9.2B — 3D Feel Spike / A-B-C Test

Date: 2026-10-08
Status: CI pending; not a production visual-quality claim.

## Why this spike

First human observation on Android:
- steering: **2/5**; character movement robotic;
- sound: **audible but too quiet**;
- positive: **pleasantly fast-paced**;
- negatives: visually basic/flat 2D, too little color, conventional multiplier gates;
- explicit proposal: investigate moving from 2D production to 3D.

One owner observation is a design hypothesis, not external-user consensus.
The accepted W9.1 public A link must remain stable until manual release.

## What the spike implements

Same authored levels, gate math, collision/score rules, pacing, replay route,
platform boundary and factory core in all variants. Existing Web publishing
remains manual-only.

A: `?variant=a` (or no variant)
  Frozen original steering (0.08 step limit), unchanged original audio
  master (0.5) and existing polished 2D scene.

B: `?variant=b`
  Same 2D scene and event content, fluid spring/damping-inspired steering
  acceleration and audio master 0.9. Existing platform mute/gesture rules
  still apply. Do not claim this is an automatic fix: physical feel matters.

C: `?variant=c`
  Same B control/sound, plus a separate game-local **WebGL2** scene with
  actual three-dimensional lit meshes and depth testing. No Three.js install,
  external assets or general-purpose factory/render abstraction. Existing
  input canvas still owns touches; pointer-transparent GPU/HUD overlays
  sit above it. Unavailable WebGL2 falls back to B visuals.

Use queries on the deployed website *only after* the CI-verified branch
is merged and the **manual Pages workflow is rerun**:

- A: `https://oddropdev.github.io/game-factory/?variant=a`
- B: `https://oddropdev.github.io/game-factory/?variant=b`
- C: `https://oddropdev.github.io/game-factory/?variant=c`

Current Pages deployment may still be the old W9.1 version.
A URL containing `variant=c` does not by itself prove 3D was published.

## CI deliverables

- unchanged A model deterministic trajectory, levels and regression suite;
- new fluid-steering unit tests;
- real WebGL2 context + depth-test-on assertion, no fake 3D CSS claim;
- portrait/landscape screenshots;
- browser touch/input, 3D unavailable fallback;
- W8 full five-level/audio/presentation regressions;
- W9 clean published package regression;
- source churn restricted to game-local and tests.
- evidence artifact `w9-2b-abc-feel-spike`, only after CI.

## Human work: short real-device comparison

Open A / B / C on the *same Android phone* and hold device/audio
volume constant. Spend ~90 seconds on each variant. For the same initial
level, rate separately:
- steering feel 1–5;
- visual appeal 1–5;
- reward of + / × gates 1–5;
- audio loudness: too quiet / good / too loud;
- choppiness or heat noticed: yes/no;
- preference and reason.

Important controls:
- Avoid `autoplay=hero` and `audio=off` during human comparison.
- The three versions are intended to isolate movement/audio from rendering;
  don't misattribute a B improvement to C's graphics.
- WebGL2 alone does **not** prove 60 fps on a real phone.
- A 3D spike is not a finished 3D art direction; the scene deliberately
  uses small procedural meshes to test technology/perception with low cost.

## Decision gate

Do not authorize five-field 3D migration until the physical device test:
- B steering owner rating reaches at least 4/5 (or a clear measurable improvement);
- C has no input/UI blockers and the phone maintains perceptually smooth play;
- C's visual quality / replay preference clearly beats B for real people.

Then 3–5 independent new players compare B vs C, without instructions.
A successful CI is only **TECHNICAL PASS**; W9.2B human decision remains open.
If C fails or looks similarly generic, pivot to 2.5D/stylized art rather
than doubling down on the renderer.
