# W9.3-4 — Owner Android Handoff

Date: 2026-10-08
Status: **READY FOR ON-DEVICE REVIEW ONLY AFTER GREEN CI + MERGE**
Scope: isolated `/3d/` W9.3 one-level PlayCanvas soft-forms Mass Runner
Decision: `GO` / `ITERATE` / `STOP`. **No owner rating is prefilled.**

## Why the device test is necessary

Playwright mobile emulation and screenshots do not measure physical Android
GPU performance, heat, battery, true browser insets, device audio or how
dragging feels in a hand. Automated CI passing is not human visual acceptance.

### Step 1 — publish the already-approved opt-in candidate manually

Only **after** the W9.3-4 PR is merged and GitHub Actions success is reviewed:

1. [Open Actions → W9 Publish Playtest to GitHub Pages (manual)](https://github.com/Oddropdev/game-factory/actions/workflows/w9-playtest-publish.yml).
2. Choose **Run workflow** on **main**. Never publish from the review branch.
3. Verify that the build **and** deploy jobs succeed; confirm the deployment URL.
4. Open `https://oddropdev.github.io/game-factory/3d/` only **after** that deployment is confirmed. This is a public URL even with noindex, so avoid broad sharing during this test.
5. Keep the accepted 2D control at `https://oddropdev.github.io/game-factory/?variant=a` unchanged.

If Pages Source has not been set to **GitHub Actions**, change it in
repository Settings → Pages before step 2. No automatic publication has
been enabled by W9.3-4.

### Step 2 — three-minute Android visual & feel test

Use a physical Android Chrome tab, portrait orientation first, with the
device held normally. Play one complete attempt and immediately retry.
Optionally rotate to landscape for 20–30 seconds.

Observe without adjusting the code:
- **Avatar** — clearly round, recognizable and responsive to growth.
- **Track and obstacles** — rounded style and convincing depth; obstacles distinct.
- **Gates and payoff** — both operation values readable without zoom; better
  operator recognizable, values visually attached to their portals even
  on high-DPI screens, reward effect not occluding next choice.
- **Environment and materials** — consistent toy-plastic palette, not
  block/voxel/wireframe; any excessive sky or repeated background distracting?
- **Mobile composition and UI** — start/retry button accessible; no text
  clipped by browser UI/notches; finger drag steers predictably; no big hitch,
  missing WebGL frame, severe heat or obvious performance collapse.
- **Compare the same phone** against the original W9.2D screenshots linked
  from W9.3-0 evidence and, if accessible, the current default 2D A.

### Step 3 — send only the tiny decision

Score each (integer 1–5):
`Avatar __ / Track __ / Gates __ / Materials __ / Mobile UI __`

Then provide:
`Overall visual quality __/5; W9.3 distinctly better than W9.2D? yes/no;`
`Android drag/play quality at least as good? yes/no; Blocker(s): __;`
`Decision: GO / ITERATE / STOP.`

GO is permitted only if overall >=4/5, no category <=2/5,
values legible, W9.3 visibly better on the same phone, controls not
degraded and there is no severe Android rendering/performance failure.

If ITERATE, cap fixes at the 1–3 highest-impact observed issues. If
STOP, preserve the known-good 2D default. W9.3 remains an opt-in
experimental /3d candidate in all cases. Do not extrapolate to
retention/commercial success from one owner's visual approval.

Following a GO, first invite 3–5 fresh mobile users for the small
original playtest protocol; *do not* auto-promote to all Factory games.

## What was deliberately not done

- No new engine, network assets, high-cost shaders or Factory abstraction.
- No changes to scoring, mass operations, collision, steering or event order.
- No auto-deployment, Android FPS assertions, or fabricated owner feedback.
