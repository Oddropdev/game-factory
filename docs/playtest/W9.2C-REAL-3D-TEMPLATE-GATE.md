# W9.2C — Replace Fake-Fullscreen Prototype with a Licensed 3D Game Template

Date: 2026-10-08
Status: **REFERENCE/TEMPLATE SELECTION — BUILD NOT APPROVED**

## Human evidence: stop the current C renderer

Owner's second real screen recording (16.87 seconds, 2210 × 1920, 30 fps)
shows an oversized navy empty scene, tiny HUD and a narrow strip of playable
3D track and player in the middle-lower viewport. Owner reports the same
on Android.

This is NOT solved by setting canvas CSS width/height to 100%:
the composition, camera framing, UI scale and visual content are broken
at the product-quality level. WebGL2 context + non-background pixel tests
can pass despite an unacceptable visual result.

**Stop expanding custom MassRunner3DRenderer.** Preserve A baseline,
B steering/audio experiment and frozen Mass Runner gameplay. No public
auto-deployment. C remains unapproved as a production path.

## Actual reusable sources (verify pinned commit and license before copying)

### First choice for fast AI-native browser integration

1. THREE.js Game Dev Starter / Cube Runner
   https://github.com/heagandev/threejs-agent-starter
   TypeScript + Vite + Three.js; playable runner starter; MIT.
   Source engine/input/scene patterns may be reused with MIT notices.
   It is NOT visually polished enough on its own: no acceptance without
   real asset and framing improvements.
2. Quaternius Ultimate Platformer Pack
   https://quaternius.itch.io/ultimate-platformer-pack
   CC0; glTF animated character (18 animations), prefabs, hazards,
   terrain, 3D numbers and mechanics. Use actual downloaded assets
   locally, not remote runtime CDNs.
3. Kenney Platformer Kit
   https://kenney-assets.itch.io/platformer-kit
   CC0 glTF modular scenery/assets.

This is a concrete copy/adapt path, not a request to write another raw
WebGL shader. Maintain the existing TS gameplay model as the single
source of truth; port/add only a scene/render adapter.

### Comparative reference — better-looking fully integrated game starter

Kenney official 3D Platformer Starter:
https://github.com/KenneyNL/Starter-Kit-3D-Platformer
Godot 4.6, MIT code and CC0 supplied assets, working camera/controller.
Valid genuinely complete starter but changes engine and requires moving
TS logic to GDScript. Treat as visual/technical bakeoff candidate only,
not automatic recommendation for the current browser-first factory.

### Secondary fallback

PlayCanvas official create-playcanvas Third-Person Controller:
https://github.com/playcanvas/create-playcanvas
MIT, TypeScript + Vite, supported current browser engine; off-the-shelf
third-person starter, not a drop-in arithmetic runner. If the imported
Three.js runner performs badly or lacks maintainable structure, compare
this before committing to a full rewrite.

### Weak fit / verify asset provenance before copy

CollinEMac/open-runner (MIT) offers real runner systems, levels,
touch/mobile controls and performance settings, but includes older
JS/modules/assets and third-party resources. Not selected merely
because its README says MIT; audit all assets.

## Visual direction (reference only; do not copy commercial artwork)

- Tall Man Run: brightly lit toy-plastic art, giant instantly legible
  multiplier gates, visible scale changes.
- Going Balls: low-friction tracking camera, velocity/surface feedback.
- Bridge Race / Stacky Dash: clean colorful course and appealing feedback.

These are references for style and design grammar. Do not take
proprietary textures, branding, characters or game files from these games.

## Smallest W9.2C implementation

**C-new** is a **separate opt-in prototype**, NOT a main game conversion.
Retire the current C output from approval comparisons; keep the public
default A untouched until human signoff.

Phase 0 — License/provenance freeze:
- pin exact upstream MIT code commit; keep copyright/license text;
- pin downloadable CC0 asset pack and preserve attribution/provenance;
- no unlicensed models or hotlinked production assets.

Phase 1 — Copy an actually runnable starter unchanged:
- show working player, ground, camera, lighting and responsive HUD;
- only add the Mass Runner-specific first level after the copied base works;
- no new generic factory abstractions or new scoring/physics engine;
- maintain B steering so visual comparisons are controlled.

Phase 2 — Single polished hero slice:
- mobile portrait 390×844 plus 360×800 and landscape 844×390;
- camera and safe-area-adaptive scaling, NOT just full-window canvas;
- at all times player, immediate decisions and track must stay visible;
- strong visual hierarchy: avatar/action in lower-middle, upcoming gates
  dominating the readable center; no giant empty navy band;
- legible minimum 16 CSS px gameplay-critical text on 390×844;
- real models/materials, proper lighting/shadows/tones;
- visually distinct + and × gate models/FX (new Mass Runner identity);
- sound audible without distortion or clipped platform mute behavior;
- no undesired scrolling, letterboxing, squashing, canvas overlays
  stealing touch input, screen cutoffs or frame-size mismatch.

Phase 3 — Evidence before human asks:
- automated Playwright screenshots of 360×800, 390×844 and 844×390;
- inspect actual output screenshots manually for composition and visual
  quality, not only non-background pixels;
- measurable HUD bounding-box/legibility, camera occupancy, WebGL
  errors and mobile-framerate logging;
- full-screen browser and home-screen launch are distinct: CSS 100dvh
  fills the available viewport, while immersive fullscreen needs browser/
  platform capability and a user gesture;
- browser build deploys through the existing **manual GitHub Pages** path;
- A/B legacy regression tests remain accepted;
- no production/default replacement before physical-device approval.

Human acceptance (next, 5 min): Android A vs imported C-new, without
autoplay. Rate steering, visual appeal, reward, legibility and smoothness;
prefer 3–5 independent players after owner confirms no viewport issues.

## Decision

- **REJECT** the self-written WebGL C as production technology/design.
- **ADOPT FOR BAKEOFF** licensed runnable 3D starter + CC0 art, keeping
  current TypeScript model/browser workflow.
- **HOLD** all claims of a successful 3D game until screenshot quality
  and real Android composition improve materially.
- Do not auto-merge an art-only CI PASS.
